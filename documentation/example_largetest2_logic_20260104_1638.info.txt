1. Offloading Layers Logic
Observation: The user noted "offloading layers to CPU/GPU... finished" appearing before the prompt was loaded and found it amusing/illogical ("message or prompt has not been loaded yet, lol!!!").
Explanation: The `offload_layers_to_cpu` method operates on the static model *weights* (parameters), not the dynamic *activations* or the *prompt*.
- Purpose: It moves a specified number of model layers from GPU VRAM to CPU RAM to make space for the inference process (KV cache and activations).
- Timing: This must be done *after* the model is initialized but *before* inference begins. It is unrelated to whether a prompt has been tokenized or loaded.
- Conclusion: The observed behavior is correct and intended. The log message reflects the movement of model parameters.

2. `torch_dtype` Deprecation Warning
Observation: The user observed "`torch_dtype` is deprecated! Use `dtype` instead!".
Explanation:
- The `ollm` library (specifically `inference.py` and model handlers) explicitly uses the `dtype` argument when initializing models (e.g., `dtype=torch.bfloat16`), complying with modern Transformers guidelines.
- The warning likely originates from the `transformers` library internals or an interaction where `dtype` is passed in `kwargs`, and `transformers` detects it and maps it to `torch_dtype` while simultaneously warning about the deprecated `torch_dtype` argument.
- Verification: Code review of `src/ollm/inference.py` confirms usage of `dtype`. No `torch_dtype` usage was found in the `ollm` source. The warning can be safely ignored as the code is compliant with the "Use `dtype`" directive.

3. `reasoning_effort` Argument
Observation: The user included `reasoning_effort="minimal"` in `apply_chat_template`.
Explanation: This argument is not supported by the tokenizer/template processor in the current environment configuration. It was removed to prevent TypeErrors or unexpected behavior during tokenization.

4. Attention Mask Missing
Observation: The user encountered "The attention mask is not set...".
Explanation:
- When generating with a batch size of 1, if the tokenizer's `pad_token_id` is the same as `eos_token_id` (or not set), the model cannot automatically distinguish padding from valid tokens.
- Fix: We explicitly created `attention_mask = torch.ones_like(input_ids)` and passed it to `model.generate`. This ensures the model correctly attends to all input tokens and suppresses the warning/error.

5. Warnings about Flash Attention / Fast Path
Observation: "flash_attention_2 is not imported" and "The fast path is not available".
Explanation: These are informative warnings indicating that optional acceleration libraries (`flash_attn`, `flash_linear_attention`) are not installed in the environment. The `ollm` library automatically falls back to standard PyTorch implementations. These do not indicate a failure but rather a non-optimized execution path.
